Как это попадёт на id.holycode.org

Форк typescript-login (Zitadel Login V2)

Login V2 на id.holycode.org — это контейнер ghcr.io/zitadel/zitadel-login:v4.19.1, Next.js-приложение из репозитория zitadel/typescript (apps/login). Все потоки — passkey, коды, пароль, регистрация, device flow, внешние провайдеры, MFA — уже там; мы меняем внешний вид и тексты, логику не трогаем.

  • Репозиторий: форк в наш GitHub octy-work/holycode-login, ветка holycode; апстрим подтягиваем по тегам.
  • Тема: Tailwind-конфиг → наши токены; компоненты Button, TextInput, Card, DynamicTheme, LanguageSwitcher, Themed — переписываются под таблицу выше.
  • Экраны: loginname (экран 1: шапка-бренд, без Back, GitHub-кнопка), authenticator (экран 2: карточки-варианты), passkey, otp/[method] (ячейки кода), password, register (плашка приглашения из previewInviteToken Daenerys, выбор почты), device, mfa, accounts, signedin, verify.
  • Тексты: остаются в hosted_login_translation (уже наши RU/EN) — форк читает их как сейчас.
  • Сборка и выкат: образ reg.oggo.app/holycode/login:<tag>, в compose почтового контура подменяется image: у сервиса zitadel-login — одна строка, делает почтовая сессия по договорённости.

Что можно сделать сегодня без форка

  • Логотип без белого квадрата — прозрачный PNG (уже перезалит) и горизонтальный знак «эмблема + HolyCode» вместо квадрата.
  • Тексты — уже наши.
  • Остальное (кнопки, Back, раскладка, карточки способов, ячейки кода, GitHub на первом экране) — только форком.

Оценка форка

4 рабочих дня: день — тема и общие компоненты; день — экраны 1, 2, 5; день — регистрация, коды, device; день — светлая тема, телефон, RU/EN, проверка всех потоков вживую. Обновление апстрима — ~час в месяц.

Риск

Апстрим меняет структуру страниц — при обновлении форк может конфликтовать; лечится тем, что мы правим стили и компоненты, а не логику страниц.

Решения приняты 26.09.2026

1 · Дизайн — принят как есть, делаем форк typescript-login.

2 · Знак в шапке — эмблема + слово HolyCode с градиентом на «Holy», как на сайте.

3 · Другие входы — GitHub, Google, Apple (аккаунт разработчика есть), Яндекс ID, Telegram. VK ID и Microsoft — нет.

Что дальше

  1. Форк — отдельная задача с этим артефактом как ТЗ (чип «Форк Zitadel Login V2 под дизайн HolyCode»): тема и компоненты, экраны 1–7, светлая тема, телефон, RU/EN, образ в reg.oggo.app, подмена image: у сервиса zitadel-login — через почтовую сессию.
  2. Провайдеры подключаю по мере появления ключей: GitHub и Google — сразу, Apple — по Services ID и .p8, Яндекс — по приложению OAuth, Telegram — после моста в форке.
  3. Пока форк в работе, на id.holycode.org остаётся Login V2 с брендингом настройками — рабочий, но не наш.
